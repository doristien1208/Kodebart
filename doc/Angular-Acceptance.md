- 封面：開始／繼續／設定可用；無存檔時繼續停用並顯示「尚無本機紀錄」；有存檔顯示 phase 標籤；重開時對話框確認，預設焦點在「保留目前紀錄」，取消不傷害進度。

- Day 1（型別與整數部分已由第二輪取代）：錯誤姓名顯示欄位錯誤並 `aria-invalid`；`友善的人` 顯示「格式不符：此欄位需為 int」；`0102` 缺處理方式時提示選擇；預覧 JSON 為技術結果；已提交紀錄鎖定並顯示 `0102`（存檔內為整數 102）；三筆未齊「完成今日交接」停用；每次輸入即保存草稿。
- 轉場：Day 1 結束只顯示工作結語與 03 筆；`night` 在按「前往第二天」時才判定，且只判定一次。
- Day 2：摘要與昨日副本可並列比較；請求覆核需先開副本；三種回覆各有文書回應與存檔事件；回覆對話框開啟時焦點在「返回核對」，關閉後焦點回到觸發按鈕；結束頁不顯示勝敗或評分。
- 矩陣（UI 層）：null覆核×介入 → 摘要「版本 2／夜間校驗／已列入安排／false」而副本仍「null／資料覆核佇列」；null覆核×無介入 → 「版本 1／待資料覆核」；false×無介入 → 「版本 1／已列入安排」。
- 路由 guard：無存檔時 `/work` 導回 `/`；phase 為 day2 時手動打 `/overnight` 導回 `/work`；phase 為 end 時「繼續」直達 `/end`。

- 存檔損毀（`'{'`）：封面顯示「無法讀取本機紀錄…」、繼續停用、原始資料未被覆蓋；確認後才以新遊戲取代。
- 儲存失敗（`setItem` 拋錯）：狀態列顯示「本機儲存不可用…」，本次仍可遊玩。
- 窄螢幕 375px：封面與工作台 `scrollWidth === innerWidth`，無橫向溢出；導航改橫向；右側摘要欄隱藏。
- 導航：工作／訊息／公告切換不觸發亂數；Day 2 閒聊句依 `smallTalkVariant` 選擇；文件標題隨畫面更新。

# 第二輪修改（2026-09-22）

依使用者指示，本輪只做兩件事：開始頁標題 glitch、第一輪歸檔表單改為「核對人員編號」。其餘章節、規則與後續事件未更動。

## 1. 開始頁標題 glitch

字體、位置與大小不變；效果只作用在 `<h1>`，以兩層虛擬元素（青色色差層＋同色錯位層）疊出帶狀水平錯位，位移 1–3px。

| 項目 | 設定 | 實測 |
|---|---|---|
| 間隔 | 隨機 5–10 秒 | 觀察 13 秒播放 2 次，間隔約 7.1 秒 |
| 單次長度 | 隨機 200–350ms | 實測 320ms 與 280ms |
| 位移 | 1–3px | keyframe 實測 `translateX(-3px)`、裁切帶 `inset(14% 0 62%)` |
| 色差 | 青色 | 實測 `rgb(145, 216, 223)`，即 `--color-primary` |

- 虛擬元素為 `pointer-events: none`，標題改為 `inline-block` 後不與選單重疊；三個選單按鈕的中心點命中測試皆為按鈕本身。
- 關閉「啟用選單動態」後 13 秒內播放 0 次，`animation-name` 為 `none`：JS 停止排程，CSS 亦以 `body.no-motion` 與 `prefers-reduced-motion` 雙重保險。

## 2. 歸檔表單：姓名改為顯示，人員編號改為輸入

- 移除「資料類別／人類員工／巴特族」欄位與標籤，移除「欄位規格：string／int」標記。
- 每筆資料版型相同：姓名為純文字（有姓名者顯示姓名，0102 與 0607 顯示「未登記」），人員編號為輸入欄位。
- 提示文字：操作說明「請依來源資料核對人員編號，完成歸檔。」；留空「請填寫人員編號。」；不符「請依來源資料填寫人員編號。」；提交成功狀態列「歸檔完成。」
- 同事訊息與右側摘要欄中提到欄位規格的句子一併改寫；本輪未新增警告、異常特效，也未解釋姓名未登記的原因。

### 前導零

人員編號在核心層改為字串保存（`ArchivedRecord.archiveCode: string`），存檔版本提高為 **v2**（key `kodebart-save-v2`）。v1 把編號存成整數，兩者不相容，因此舊檔會被 schema 明確拒絕而非誤讀。

實測：提交後 localStorage 原始 JSON 為 `"B102":{"archiveCode":"0102",...}`；重新載入後畫面仍顯示「人員編號：0102」；輸入 `102`（少前導零）被判定為不符。

### 保留的邏輯

「缺少拒絕紀錄」的 false／覆核兩個選項、四格結果矩陣、夜間判定、事件紀錄與 Day 2 三種回覆全部未動。實測完整跑完 Day1 → overnight → Day2，事件序列為 `archive ×3 → day1.complete → night.resolved`，Day 2 在介入分支顯示「版本 2／夜間校驗／已列入安排」。
