## 1. UI：資料作業桌面，不是長表單

重用 `ui/desktop`、WindowManager／WindowShell，不再造作業系統。

- 工作平台只保留工作與公司公告，移除通訊／郵件重複 app 導航；從桌面或底部視窗列開啟其他 app。不留 TODAY／固定 log 第三欄。
- 工作窗主要分為佇列、當前案件、底部處理列。佇列有種類、待辦／已送件／待補、依賴原因；獨立任務可選順序，有資料依賴才锁。送一筆不等於結束一天。
- 當前案件顯示來源摘要、玩家採用值與文件入口。原始 JSON、完整文件、轉換預覽、log 不全部堆在正文。
- 文件可並排查閱；提供並排／還原位置按鈕，不只靠拖曳。最小化／切換案件保留草稿，舊副本唯讀。
- JSON 視窗呈現 `input / rule / output`、逐列差異與來源。技術 JSON 的 false／null 有領域意義對照；主操作不叫 false／null，不露 seed／條件 ID。
- terminal 根據實際事件顯示驗證、建立輸出、保存、入佇列與數量。防連點；失敗保留輸入。不假裝打 API、不固定數秒空轉、不保存前顯示成功。
- 沿 `doc/DESIGN.md` 的冷色像素外框、既有 token、Saira／中文正文，縮減海報式按鈕／多餘留白；不改色碼／字型 token，不生成素材。
- 1366×768 主要處理列可達，文件／表格內部捲動但不裁表單。375px 採單窗切換，JSON 可內部橫捲，頁面不 overflow。視窗 icon 有繁中 accessible name，支援鍵盤與 reduced-motion。

## 2. 三種工作串起來

### A｜歸檔與補件

手輸編號，只驗非空白文字、原樣保存前導零。不恢復來源自動填入，不驗與來源相等。普通件穿插例外，不把故事案件標成特殊紅卡。Day 3 黃品蓉雙版本案件沿既有 IDs／決定，讓查閱與歷程真正好用；選依據不會自動讓編號正確。

### B｜附件關聯與覆核

新增可操作工作：選引用附件，查對象、版本、回覆者與範圍；也可保留缺漏送覆核。至少兩案：Day 4 的 0314（窗口收件不是本人回覆，0521 的附件可以被誤選），Day 5 的紙本交接（電子回條不是箱子抵達）。文案與文件見內容包。

只驗附件存在、選項合法、必要欄位，不以適用性擋成唯一正解。保存附件 ID＋不可變版本快照、對象、依據、去向與玩家實際採用值。後日回條指出具體關聯問題，而非提交當下公布答案。

### C｜批次轉換與交付

Day 4 小批次，Day 5 擴大範圍，Day 6 整合。選映射／缺漏策略，看逐列 JSON 再交付；延伸既有 field-map，不只是搬頁面。

輸入至少包含前階段**實際保存的編號、回覆狀態、選定附件**，不能拿另一份固定標準答案假裝關聯。原始來源、玩家採用值、系統生成值分清。保存輸出供後日覆核／郵件使用。兩條合法策略有不同待補量與回條；缺漏補成值不等於當事人同意。
