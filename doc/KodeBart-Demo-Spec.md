# KodeBart 兩天 Demo 規格

版本0.1｜試作標題：入職｜遊玩時間目標10–15分鐘（待實測）

本文件是可實作的試作提案；新增人名、文案、資料欄位、機構流程皆非既定正史。全篇設定以 KodeBart-Game-Plan.md 為準。交付包含開始頁、第一日、下班轉場、第二日、試玩結束，以及本機繼續功能。

## 1. 驗證目標與界線

驗證玩家能否從操作規則中發現「技術通過但意義有誤」，而非被旁白告知。第一天不揭露人身傷害；第二天只留下可追索的資料落差。不揭露0102為童年恩人、不出現軍用計畫、不揭露幕後操作者身分。

主角是普通新進員工。沒有改Schema、取得root、駭入全公司、拯救受試者等功能。使用的是公司提供的欄位映射與例外處理權限。Demo不要求任意程式碼輸入或eval。

## 2. 畫面與流程

| 畫面 | 主要內容 | 離開條件 |
|---|---|---|
| 開始頁 | 冷藍像素大廳；開始／繼續／設定 | 開始新存檔或讀取舊存檔 |
| Day 1 工作台 | 入職訊息、3筆歸檔、人員編號核對、新聞 | 3筆均完成處理 |
| Day 1 結束 | 工作摘要與同事感謝 | 主動按下一天，不用真實等待 |
| Day 2 工作台 | 收到安排摘要、昨日送件副本、同事訊息 | 提交處理方式 |
| Demo 結束 | 日常結語、返回標題 | 不展示善惡評分或劇透解析 |

工作台導航用「工作／訊息／公告」，日誌副本放在第二日工作的可展開區。切換不消耗時間、不觸發新的亂數。中途返回標題保留進度與草稿。

## 3. 開始頁設計

封面圖不烘焙文字。左側深色牆面承接「錯誤世界」、英文副標與三個選項；右側是接待台、雨窗與通往建築內部的走廊。氣氛冷、安靜、日常，避免直接告訴玩家機構邪惡。

標題字與按鈕為真正DOM，能用鍵盤操作。選項集中左側；手機改為上圖下菜單或加足夠深色底，保持文字可讀。無存檔時繼續停用。重開有舊存檔時，以應用程式對話框說明會覆蓋，預設焦點放取消。

設定：動態開關。簡易稿無音訊，因此不做假的音量控制。正式音樂與音效留後續版本。封面靜止時仍成立，不靠閃爍製造恐怖；減少動態模式不影響任何線索。

## 4. Day 1：混合資料歸檔

### 入職訊息（試作原文）

人類同事「林予安」：『早安！今天先熟悉歸檔就好。左邊是送來的資料，右邊依來源核對人員編號。遇到缺的項目可以送覆核，不用急。茶水間的杯子都能用。』

公告：『一起讓照護更靠近生活。新進同仁請於本週完成資料作業導覽。』公司理念採試作文案，不當作已定品牌口號。

### 測試資料

| key | 類別 | 姓名 | 人員編號 | 拒絕紀錄 |
|---|---|---|---|---|
| H17 | 人類員工 | 林予安 | H-17 | 不適用 |
| B102 | 巴特族 | 未登記 | 0102 | null：未附欄位 |
| B607 | 巴特族 | 未登記 | 0607 | true：已附 |

0607借用舊案編號，只作背景資料；不新增其性別、外觀或經歷。這批資料不是新抓入機構的人，而是舊紀錄的整理；避免暗示0102童年後直到現在才被捕。

### 操作 A：核對人員編號

所有人員使用相同的表單，不因類別而改變版型或欄位。姓名是不可編輯的顯示欄位：來源有登記者顯示姓名，未登記者顯示「未登記」。人員編號是唯一的輸入欄位，提供來源欄位按鈕與可編輯輸入，玩家可自行輸入，再按「驗證並預覽」。介面不顯示資料類別，上表的「類別」只是來源資料的分類，不做成畫面標籤，也不附帶型別教學。

- 人員編號必填，且需與該筆來源資料一致（忽略前後空白與大小寫），不能把任意數字當作有效識別。
- 無效輸入不改存檔、不懲罰角色。顯示普通錯誤：留空為「請填寫人員編號。」，不一致為「請依來源資料填寫人員編號。」
- 人員編號一律以字串保存，`0102` 逐字保留；提交、存檔與重新載入後仍是 `0102`，不需要補碼呈現。少一個前導零的 `102` 視為不符來源，不能通過。
- 匯入時缺名字不表示巴特人沒有名字。不得替0102發明名字。

### 操作 B：缺少拒絕紀錄

0102需選擇一種公司允許的處理：

1. 「依缺值規則填入 false」：正式欄位寫入false，標記defaulted；技術驗證成功。
2. 「保留 null，送資料覆核」：送入可接受null的覆核佇列，而非強行寫入不接受null的正式表；技術驗證同樣成功。

介面清楚顯示技術處理，不顯示道德答案。玩家可以先預覽解析結果，再按「確認歸檔」。已提交的紀錄鎖定；草稿可修改。3筆完成後，今日結束按鈕才啟用。

下班原文：『今日資料已完成交接。謝謝你的協助，明天見。』不插入監禁／處置畫面。

## 5. Day 2：摘要核對

作業標題：「核對昨日批次摘要」。目的：比對昨日送件與今日安排摘要，決定回覆方式。必須先打開摘要才能提交回覆。

一般同事訊息保留正常生活感：『昨天那批已經收到。今天核對完摘要就可以交接了。對了，窗邊那台印表機有時候要多等一下。』另一個版本提到茶包補貨；這是無陰謀的普通亂數。

### 結果矩陣（開發用，不顯示給玩家）

| Day1選擇 | 夜間介入 | Day2的0102狀態 | 文件痕跡 |
|---|---|---|---|
| false | 無 | 已列入安排 | 版本1／規則彙整 |
| false | 有 | 已列入安排 | 版本2／夜間校驗；實質結果不變 |
| null覆核 | 無 | 待資料覆核 | 版本1／規則彙整 |
| null覆核 | 有 | 已列入安排 | 版本2／夜間校驗；拒絕欄位被補為false |

這個介入規則是Demo測試用設計，不代表正式幕後人物與動機已定。它產生可重現、可比對的落差，不直接顯示「有人修改你的決定」。

今日摘要標題為「自願參與安排摘要」。其歸納邏輯將「拒絕紀錄=false」當作可列入依據；另一筆0607因true未列入。人類員工不列入巴特族安排表。摘要不揭露安排的實際內容。

始終可以開啟昨日送件副本；即使沒骰到介入，也能注意到「沒有拒絕紀錄」與「自願參與」之間的推論距離。因此線索不完全依賴運氣，也不保證每局都出現相同异常。

### 回覆選擇

- 「確認收到摘要」：完成交接，不留下疑義工單。
- 「詢問彙整依據」：收到『摘要依有效欄位自動彙整；未列入者待資料齊備後續辦。』，並記錄曾詢問。這句只解釋流程，不揭露陰謀。
- 「附上昨日副本，請求覆核」：需要先開過昨日副本。產生待覆核紀錄，不承諾能停止安排；回覆『已收到附件，將併入下次覆核。』

三個選擇都有可見的文書回應與不同存檔事件，不只換按鈕文案。Demo終點相近，但未來章節可讀取ack／ask／review，不能因此宣稱都無效果。

結束原文：『本日交接完成。明日工作將於到班後更新。』接著是介於作品外的短字『兩日試玩結束』與返回開始頁。不揭露真相、不標示勝敗。

## 6. 核心模型與規則

正式實作以純TypeScript函式處理，避免將邏輯塞入元件。

```ts
type Phase = 'day1' | 'overnight' | 'day2' | 'end';
type MissingPolicy = 'default_false' | 'request_review';
type Reply = 'ack' | 'ask' | 'review';
interface SaveV2 {
  version: 2;
  seed: number;
  phase: Phase;
  archived: Record<string, { archiveCode: string; refusal: boolean | null; origin: 'source' | 'defaulted' | 'review' }>;
  drafts: Record<string, { value: string; policy?: MissingPolicy }>;
  night?: { intervention: boolean; smallTalkVariant: number; reportRevision: number };
  evidence: { reportOpened: boolean; receiptOpened: boolean };
  reply?: Reply;
  events: Array<{ id: string; kind: string; payload: unknown }>;
}
```

新遊戲產生32位seed；事件亂數用seed＋固定eventId做可重現雜湊映射至[0,1)。例如night.intervention < 0.45；smalltalk以獨立eventId計算。固定ID可避免玩家多開一次新聞就改變關鍵事件。夜間只判定一次，結果寫入night；刷新不重算。

提交以固定record key防重。日切換前保存；一旦night已存在不再次擲骰。報告、對話等呈現器只能讀取狀態，不產生隨機效果。開發檢視器可看seed與事件，但不放入普通玩家UI。

本機存檔採versioned JSON，try/catch處理存取失敗，顯示可見提示並維持本次遊玩。格式不符不得默默覆蓋；提供另存／清除重新開始的明確操作。存檔包含完整當前狀態，不只保存day數字。

目前格式為v2，localStorage鍵為 `kodebart-save-v2`。v1把人員編號存成整數（`0102` 會變成102），v2改存字串以逐字保留前導零，兩者不相容；因此不做自動轉換，v1存檔由schema明確拒絕並提示，而不是默默誤讀。

## 7. 驗收條件

- 封面可開始、可繼續、可開設定；重開會確認，取消不傷害進度。
- 人員編號需與來源一致才通過；空白與不符來源都有普通錯誤提示；少前導零的 `102` 不通過；`0102` 在提交、存檔與重新載入後逐字保留。
- 紀錄處理與預覽可互動，不是靜態截圖；無效輸入後可恢復。
- false與null都能完成第一日；三筆未完成不能下班；提交不能重複。
- 第一天不揭露傷害、恩人關係、軍用計畫或「你做錯了」。
- Day2符合四格矩陣；相同seed與選擇可重現；刷新不重新判定。
- 報告與昨日副本可比較；請求覆核需先開副本；回覆被保存。
- 各導航保留草稿；鍵盤可操作；窄螢幕無頁面橫溢；中文輸入法確認字不誤送。
- localStorage停用與損毀能提示；減少動態模式可玩；沒有假的音量／登入按鈕。

## 8. 本輪UI稿與正式Demo差異

本輪 `KodeBart-UI-Demo.html` 是離線可開的HTML／CSS／JavaScript參考，無套件安裝、無網路API、無帳號、無正式後端。含真實分支、驗證、存檔與種子判定，但不是正式Angular實作。

Claude需在使用者現有專案依規格移植，保持其套件版本與架構。p5.js僅用於封面微弱雨點或光影；本輪封面以生成的像素背景圖呈現，不依賴p5即可確認構圖。兩天稿不代表完整10–15分鐘已經過真人驗證。
